## Вручную

1. Открыть http://localhost:8080, раскрыть сводку, «Паспорта пожаров».
2. В «Наблюдения» выбрать «Термоточки и гарь», открыть один из паспортов выше.
3. «После пожара»: переключить все годы и вкладку «Растительность».
4. На вкладке «Снимок» включить «Сравнить с 2019», подвигать разделитель.
5. Закрыть и открыть снова: скачивание из спутникового архива не повторяется.
6. «Осмотреть участок» → выбрать место → «Далее»: цель уже «Оценить восстановление».
   Сохранение и отдельная страница задания используют существующий механизм.

## Автоматически

Итог прогона: 59 целевых backend-тестов и 13 E2E-сценариев прошли;
production build, TypeScript и линтеры затронутого кода — без ошибок.
Скриншоты шести сочетаний экрана/темы проверены; на 375×740 исправлена
высота снимка, чтобы легенда оставалась видимой без прокрутки.

Из корня репозитория с установленными зависимостями:

```bash
uv run --package firewatch pytest backend/tests/test_vegetation.py backend/tests/test_acquire.py backend/tests/test_events.py backend/tests/test_inspections.py
cd frontend
npm run build
APP_URL=http://localhost:8080 npm run test:e2e -- tests/e2e/vegetation.spec.ts
```

Сквозные тесты проверяют реальный API и все 24 кадра, неизменность кэша,
выбор каждого года, сравнение, возврат, создание задания и его отдельную страницу.
Адаптивность и доступность: 1440×800, 768×1024, 375×740, светлая/тёмная темы.
Сбои источника/картинок/опроса моделируются перехватом только в соответствующих
тестах; реальные проверки спутниковых данных не используют подмен.
Тест создания сохраняет одно помеченное `E2E vegetation` задание в локальной базе.

`probe.py` — отдельный первоначальный эксперимент диапазонного чтения COG:
он измеряет трафик и окно, а не весь пользовательский путь.
