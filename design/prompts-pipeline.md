# Промпты по этапам

Запускать по порядку, каждый после завершения предыдущего. Перед первым шагом выполнен промпт 0, агенты `designer` и `design-jury` лежат в `.claude/agents/`.

---

## Промпт 1 — аудит текущего дизайна

```
Используй агента design-jury. Код не меняй.

1. Подними проект локально (или открой задеплоенную версию: <URL>).
2. Сними скриншоты через Playwright на 1440, 768 и 375 px для всех экранов: обзор региона, карточка сцены (до/после), «Динамика и статистика», «Конвейер», выгрузка справки. Сохрани в design/screens/iteration-0/.
3. Оцени по рубрике агента. Отдельно для каждого экрана:
   - сколько слов интерфейса (без чисел и названий из данных);
   - список текстовых элементов, которые можно удалить без потери смысла;
   - список плашек, карточек и панелей, которые можно убрать или объединить;
   - где огненные цвета используются не для данных.
4. Результат — в design/reviews/iteration-0.md.
```

## Промпт 2 — три наброска параллельно

```
Запусти три субагента designer параллельно. Код приложения не трогать: каждый делает статичный HTML в design/directions/<A|B|C>/index.html.

Каждый рисует одни и те же два экрана на реальных данных проекта (бери из API или фикстур, ничего не выдумывай):
1) обзор региона с картой гарей, итогом в гектарах и таймлайном;
2) карточка сцены со слайдером «до/после» и разбивкой по степени поражения.

Все три обязаны соблюдать раздел «Дизайн: правила» в CLAUDE.md и учитывать design/reviews/iteration-0.md.

A — «Вычитание». Текущий стиль, но минус половина текста и плашек. Карта на весь экран с зумом на регион вместо глобуса, одна основная панель, огненные цвета только у данных. Цель: то же приложение, только в два раза спокойнее.

B — «Тепловизор». Интерфейс холодный и приборный, графитово-серый, без цвета. Цвет только в данных: тепловые палитры и SWIR-композиты. Главный момент — пролёт спутника: полоса сканирования проходит по региону, за ней появляются термоточки, ложные гаснут с пометкой причины, затем прорисовывается контур гари.

C — «Планшет». Светлая картографическая эстетика: сетка лесных кварталов, условные знаки, снимки оформлены как фотопланшеты. Справка о площади гари выглядит как документ с номером, датой и подписью.

После этого design-jury оценивает все три в одном отчёте design/reviews/directions.md: сравнительная таблица баллов, скриншоты рядом, рекомендация и список удачных решений из проигравших направлений, которые стоит забрать.
```

## Промпт 3 — применение выбранного направления

```
Выбрано направление <A|B|C>, из других забираем: <список>.

1. Зафиксируй финальные токены в design/tokens.md и перенеси их в CSS-переменные или конфиг Tailwind.
2. Переведи существующие компоненты на новые токены. Логику, API и данные не меняй; если без этого не обойтись — сначала спроси.
3. Порядок: токены → обзор → карточка сцены → статистика → остальное.
4. После каждого экрана: скриншоты, затем design-jury. Повторяй, пока экран не получит PASS, и только потом переходи к следующему.
5. Коммить после каждого экрана с PASS.
```

## Промпт 4 — полировка под питч

```
Используй агента designer, затем design-jury.

1. Справка о площади гари: печатная версия и PDF, которые выглядят как настоящий документ. Это финальный артефакт демо.
2. Сценарий демо на 30 секунд: регион → термоточки → отсев ложных → контур гари → справка. Сделай так, чтобы весь путь проходился в 4–5 кликов без ожиданий (кэш, заранее загруженные данные).
3. Тест проектора: скриншоты на яркости 30% и уменьшенные до размера, видимого с 5 метров. Всё, что не читается, — исправить.
4. Состояния пусто, загрузка, ошибка на всех экранах демо.
```
