## Пробелы по важности (для баллов раздела 4 и удобства пользователей)

1. **Критично для UX/демо, не для баллов метрики.** Режим «Прямоугольник» рисуется НЕ перетаскиванием (drag), а двумя отдельными кликами по противоположным углам — подсказка «Кликните два противоположных угла» появляется, но только ПОСЛЕ включения режима, мелким текстом в левой панели, а не на карте. Первая интуитивная попытка (drag) не рисует прямоугольник, а панорамирует/зумит карту — в одном прогоне это увело карту с Нижнего Поволжья аж до Москвы и Украины. Для жюри с 3–5 минутами на демо это реальный риск неловкой паузы, если оператор дёрнет мышью как для рисования.

2. **Средняя важность, влияет на подкритерий 2 (атрибуты контуров).** Дефолтный экспорт «Контуры гарей» не даёт единого атрибута класса степени поражения на контур (только сумму площадей по 3 степеням `sev1_ha/2/3`). Формально критерий «идентификатор контура, класс степени поражения, площадь» выполняется только если проверяющий догадается переключить тумблер на «Степени» — иначе в первом же скачанном файле поле `severity`/`severity_label` не найдётся. Стоит либо переименовать дефолтный режим понятнее («по контурам» vs «по степеням» — сейчас оба названы похоже: «Контуры гарей» / «Степени»), либо сделать «Степени» выбором по умолчанию, поскольку он ближе к формулировке критерия.

3. **Средняя важность, для эксперта регионального ведомства.** Выгрузка слоя «Степени» — тяжёлая операция (212 тыс. объектов на всю территорию, файл «десятки мегабайт», предупреждение показывается, но по факту скачивание в наблюдавшемся прогоне заняло больше 15 секунд, до ~30–40 с). Предупреждение в UI корректное и честное, но нет прогресс-бара/процента — специалист, которому «нужно ответить за минуту», может решить, что зависло, и уйти со страницы.

4. **Низкая важность, для жюри.** На вкладке «Обработка сцен» нет короткой пояснительной подсказки для человека, который видит интерфейс впервые (жюри): что такое «сцена», откуда её взять, зачем нужен «Эталон (необязательно)». Специалисту ведомства это, скорее всего, не нужно (обученный пользователь), но для 3–5-минутной демонстрации жюри эта вкладка выглядит как «сложный технический экран», без объясняющего текста рядом.

5. **Низкая важность, косметика.** В отчёте (`report`) есть блок `restoration` (стоимость восстановления в рублях) — полезное дополнение сверх ТЗ, но условные ставки помечены как «условные... замените региональными нормативами» прямо в JSON-ответе API. Если жюри откроет JSON или XLSX без пояснений на защите, цифры в рублях могут быть восприняты как настоящая оценка ущерба, а не демонстрационная — стоит либо явно вынести disclaimer на первый план UI при показе этого блока, либо не выводить его в кратком представлении для жюри.

6. **Не проверено в этой сессии.** Запуск сервиса «по README.md с нуля» и повторяемость метрики (< 0.005) — за пределами объёма задачи (сервис уже был поднят), но это тоже часть подкритерия «Работоспособность» и стоит проверить отдельно перед защитой.

- **Работоспособность (0/4):** похоже на полные 4 — есть REST API, пространственно-временной запрос (полигон и bbox) работает, ответ за секунды, без ручного вмешательства.
