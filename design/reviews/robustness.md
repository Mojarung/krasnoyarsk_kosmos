# Кордон — надёжность интерфейса: адаптив, пустые состояния, клавиатура, ошибки, доступность

Дата: 2026-09-19. Приложение проверялось на `http://localhost:5173`, Vue 3 + Vite, Playwright (headless Chromium) + axe-core 4.x. Тема ставилась через `localStorage.fw-theme` до загрузки, после загрузки проверялась положительным контролем (`documentElement.classList.contains('dark')` сверялась с запрошенной темой на каждом прогоне — расхождений не было ни разу, обе темы подтверждены реально переключёнными).

Скрипты проверки лежат в scratchpad-сессии (`C:/Temp/claude/.../scratchpad/*.mjs`) и воспроизводимы локально при работающем dev-сервере.

Правки в код НЕ вносились — только поиск и документирование.

## Сводка находок по severity

### Критично

1. **QueryPanel и InsightPanel полностью исчезают на ширине < 1024px, без какой-либо замены** — ширины 390, 768, 950, 1000, 1023 (адаптив). Кнопки-переключатели панелей («Свернуть панель запроса», «Открыть подробную аналитику», «Скрыть панель») остаются в DOM, но `offsetParent === null` (реально невидимы и некликабельны). Альтернативного входа (гамбургер, bottom sheet, свайп) нет нигде в коде. Пользователь телефона/планшета/окна ноутбука уже с браузером не на весь экран не может задать территорию, период, слои, фильтры карты и не видит сводку/разбор/сравнение сцен — доступны только карта, таймлайн и текстовый запрос к агенту.
   - Точная причина: `frontend/src/App.vue:70-71` — `<QueryPanel ... class="... max-lg:hidden" />` и `<InsightPanel ... class="... max-lg:hidden" />` (Tailwind `lg` = 1024px), без парного мобильного варианта.
   - Подтверждено бинарным поиском границы: 1023px — панелей нет, 1024px — обе на месте (`territoryPanel visible: false/true`).
   - Скриншоты: `adaptive-1023-panels-gone.png`, `adaptive-1024-panels-present.png`, `adaptive-390-mobile.png`.

### Serious

2. **axe-core `nested-interactive` (serious) — воспроизводится на ВСЕХ 6 проверенных состояниях** (сводка/разбор/карточка сцены × светлая/тёмная тема). Поля периода «с … / по …» — это `<button>`, внутри которого лежит `<input type="date" tabindex="-1" aria-hidden="true">`, используемый только для вызова `showPicker()`. Interactive-в-interactive — невалидный паттерн; `aria-hidden`+`tabindex=-1` не гарантированно прячет элемент от вспомогательных технологий (сообщение axe: «Using a negative tabindex... does not prevent assistive technologies from focusing the element»).
   - Источник: `frontend/src/components/common/DateField.vue`, строка с `<input ref="input" type="date" tabindex="-1" aria-hidden="true" ... />` внутри `<button>`.
   - Селекторы axe: `.rounded-2xl.bg-surface-3.py-2:nth-child(1)` и `:nth-child(2)` (поля «с»/«по» в панели «Период»).
   - Скриншоты: `axe-dark-overview.png`, `axe-light-overview.png` (тот же дефект в `axe-dark-drill.png`, `axe-light-drill.png`, `axe-dark-scene.png`, `axe-light-scene.png` — панель Период видна во всех состояниях).

3. **axe-core `color-contrast` (serious) — карточка сравнения сцены, обе темы**, статистика по степени пожара («слабая/средняя/сильная», га):
   - Тёмная тема: `#d2382f` на `#232020` → коэффициент **3.34** (нужно ≥4.5 для обычного текста 14px). Селектор `.rounded-2xl.bg-surface-2.py-2:nth-child(4) > .text-sm.font-semibold.tabular-nums`.
   - Светлая тема: `#e5b81c` на `#f6f2ee` → коэффициент **1.68** (провал сильный), и `#c85312` на том же фоне → **4.00** (тоже ниже порога). Селекторы `:nth-child(2)` и `:nth-child(3)` того же паттерна.
   - Источник: `frontend/src/components/panels/SceneCompare.vue`, строка `:style="{ color: 'var(--sev-' + (index+1) + ')' }"` на фоне `bg-surface-2` — токены `--sev-1/2/3` не проверялись на контраст против этого фона ни в одной теме.
   - Скриншоты: `axe-dark-scene.png`, `axe-light-scene.png`, `scene-card-compare.png`.

### Проверено, дефектов не найдено (перечислено по требованию задания — тоже результат)

4. **Адаптив по ширинам 1920/1440/1280/1024/768/390** (высота 900/1080) — ни на одной ширине нет горизонтального скролла (`scrollWidth - clientWidth = 0` везде) и нет реальных наложений плавающих панелей (после исключения ложных срабатываний, см. «Методологические замечания» ниже).

5. **Низкие высоты 1440×720 и 1280×680** — при открытии секции «Фильтры карты» (по умолчанию она свёрнута, `aria-expanded="false"`) контейнер `.thin-scroll.overflow-y-auto` корректно переходит в состояние прокрутки (`scrollHeight 625 > clientHeight 455/503`), кнопка «Сбросить» достижима скроллом. Ни горизонтального скролла, ни блокировки контента не найдено. Скриншоты: `low-height-filters-scrollable-1024x768.png`, `low-height-filters-scrollable-1440x720.png`.

6. **Пустое состояние (Калмыкия, апрель 2019, гарей нет)** — задано через строку запроса агенту. Сводка корректно показывает нули (`0 га`, `0 контуров`, `0 сцен`, `слабая/средняя/сильная — 0`), «Нужны посадки — 0 га», а «Когда горело» — текстовое пояснение «за период гарей нет» вместо пустого графика. Блок «Крупнейшие гари» корректно скрывается целиком (не оставляет пустую рамку). Разметка не ломается. Скриншот: `empty-state-kalmykia-apr2019.png`.

7. **Клавиатура: 30 Tab от честной загрузки** (`about:blank` → адрес приложения, без `reload()`, старт `document.activeElement === BODY`) — фокус идёт по разумному DOM-порядку (карта → атрибуция карты → строка запроса → 4 подсказки → Конвейер/алерты/документация/тема → свернуть панель → секции Территория/Период). Ловушек фокуса не найдено, порядок не прыгает по экрану хаотично. Видимость фокуса подтверждена рендером полной строки `box-shadow` (не усечённой) — как на нативных ссылках/canvas, так и на кастомных кнопках (`--tw-ring-color` реально закрашен, не прозрачный); индикатор на кастомных pill-кнопках визуально бледноват (полупрозрачный персиковый ring ~58%), но присутствует — не дефект, отмечено как наблюдение.

8. **Esc корректно закрывает** и диалог «Конвейер» (`role=dialog`, count 1→0), и «разбор» (расширенная панель аналитики с вкладками Сводка/Динамика/Восстановление/Ложные тревоги) — оба сценария подтверждены до/после.

9. **Смена темы во время открытого диалога «Конвейер» блокируется правильно**: обычный (не форсированный) клик по кнопке темы, когда открыт модальный оверлей, у Playwright таймаутится («element is not visible/actionable») — то есть оверлей действительно перехватывает клики фона, что и требуется от модалки.

10. **Двойной клик по «Выгрузить»** не создаёт видимого меню/диалога (кнопка — прямое действие, не дропдаун), ошибок в консоли и `pageerror` не возникло.

11. **Быстрое переключение секций QueryPanel подряд** (3 круга по Территория/Период/Слои/Фильтры карты с паузой 80мс) — ошибок в консоли/странице не возникло.

## Методологические замечания (чтобы не читать находки некритично)

- Автоматический детектор «элемент обрезан по низу вьюпорта» на первом проходе дал много ложных срабатываний (кнопки внутри свёрнутой по умолчанию секции «Фильтры карты» — `aria-expanded="false"`, `opacity: 0`, родитель `overflow-hidden` высотой 0px, но `getBoundingClientRect()` для дочерних кнопок продолжает мерить «естественную» раскрытую высоту анимации grid-template-rows). Эти находки исключены после проверки `aria-expanded`, `opacity` и факта, что контент невидим намеренно (см. пункт 4/5 выше — при реальном раскрытии всё работает).
- Аналогично, наивная проверка `outline`/`box-shadow` через `getComputedStyle` на кастомных кнопках показала `boxShadow: rgba(0,0,0,0)...` при обрезке строки до 60 символов — при чтении полной строки там же обнаружился реальный непрозрачный ring дальше по списку теней (браузер комбинирует несколько shadow-слоёв, первые — заглушки от неиспользуемых Tailwind-переменных). Итоговый вывод про фокус основан на полной строке `box-shadow`, а не на усечённой.
