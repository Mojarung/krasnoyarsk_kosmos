# Паспорт пожара

Паспорт связывает наблюдения VIIRS и результаты анализа гари Sentinel в одну
объяснимую историю. Это **гипотеза связи наблюдений**, а не реестр подтверждённых
происшествий. Статусы «горит»/«потушен» и направление распространения не выводятся
из пропусков между пролётами.

## Как проверить вручную

1. Открыть приложение, выбрать «Вся территория» и весь доступный период.
2. В сводке нажать **Паспорта пожаров**, выбрать **Термоточки и гарь**.
3. Открыть первое событие. На текущем наборе это `bs-FE13548`: 55 термоточек,
   наблюдение 23 августа 2022, снимок после пожара 27 августа, около 3 222 га гари.
   На карте остаются только наблюдения этого события.
4. Проверить историю, **До и после**, закрыть сравнение: вернётся тот же паспорт.
5. Прокрутить до степени поражения, предварительного плана восстановления и
   **Как связаны данные**. Здесь показаны правило связи и расстояние до гари.
6. **Скачать JSON** выгружает весь паспорт с геометрией и основаниями связи.
7. Вернуться стрелкой или Escape. Проверить «Только термоточки» и «Только гарь»:
   отсутствующие наблюдения обозначены как «Нет данных», а не как нулевой ущерб.
8. Закрыть паспорта. Открыть паспорт кликом по природной термоточке либо гари.
9. Повторить для Ростовской, Волгоградской областей и Калмыкии. Проверить также
   Астраханскую и Саратовскую области, другой сезон и собственный прямоугольник.
10. Переключить тему; проверить ширины 1440, 768 и 375 px. Содержимое панели
    прокручивается отдельно, заголовок и закрытие остаются доступны.

Список учитывает выбранную территорию и период. Открытый паспорт показывает
событие целиком — это явно подписано. Фильтры отображения карты не меняют паспорт.

## API

`GET /api/v1/events` принимает обычные параметры bbox/периода проекта.
`POST /api/v1/events` принимает `geometry` или `bbox`, `date_from`, `date_to`.
Параметры списка: `status=all|linked|hotspot_only|burn_only|ambiguous`, `offset`,
`limit` (1–100). Детали: `GET /api/v1/events/{id}`.
Поиск по объекту: `GET /api/v1/events/resolve?hotspot_id=...` либо `?scene_id=...`.

```sh
curl -fsS 'http://localhost:8000/api/v1/events?bbox=35,43,52,55&date_from=2019-01-01&date_to=2024-12-31&status=linked'
curl -fsS 'http://localhost:8000/api/v1/events/bs-FE13548'
curl -fsS 'http://localhost:8000/api/v1/events/resolve?scene_id=BS_tr_000109'
```

## Правила и ограничения

- Используются только готовые сцены и природные термоточки: `code=1`, не
  постоянный источник. Эталонные маски не участвуют в связывании.
- Термоточки объединяются цепочкой соседства до 1,5 км и 48 часов между
  соседними наблюдениями. Это эвристика; цепочка может охватывать больше 1,5 км.
- Связь с гарью: термоточка внутри/до 375 м от предсказанного контура и между
  датами снимков Sentinel включительно (UTC). Временное окно не означает,
  что пожар продолжался всё это время.
- Один кандидат связывается; несколько разных событий остаются раздельными
  и перечисляются как возможные связи. Каталожный `fire_event_id` группирует BS.
- Членство в событиях рассчитывается по всему набору, не зависит от текущей
  области запроса. AF-ID стабилен при перестановке/перезагрузке одинаковых
  наблюдений, но может измениться при добавлении более ранних наблюдений.
- Площадь деталей рассчитана в метрической системе исходной сцены. Для
  нескольких сцен пересечения считаются один раз; выше степень — выше приоритет.
  В списке для нескольких сцен площадь `null` до расчёта объединения в деталях.
- Карта геометрически упрощена; числовая площадь считается **до** упрощения.
- План восстановления использует существующие правила проекта. Для
  пересекающихся сцен доли земного покрова нормируются к объединённой площади;
  это предварительная оценка, требующая проверки специалистом.
- Качество результата ограничено существующей моделью гари. Паспорт не
  добавляет новых снимков и не доказывает принадлежность к одному пожару.
- Индекс и детали кешируются с версией данных; при обновлении набора кеш
  становится неактуальным автоматически. Холодный запрос медленнее повторного.

## Автоматические проверки

При запущенном API и наполненной базе:

```sh
cd frontend
npm ci
npx playwright install chromium
npm run dev
# В другом терминале из frontend:
npm run test:e2e
# Собранный интерфейс (нужна актуальная сборка web):
APP_URL=http://localhost:8080 npm run test:e2e
```

В development запускаются также проверки прямого клика карты, рисования
области и палитры при смене темы: они читают готовность MapLibre через имеющийся DEV-диагностический
объект, но взаимодействуют настоящей мышью, не вызывают обработчики/Pinia.
В production эти три диагностических сценария пропускаются.
Остальные сценарии работают без DEV-интерфейсов и без подмены данных;
только сценарий сетевой ошибки намеренно обрывает один запрос.

Отчёт Playwright: `frontend/playwright-report/index.html`.
Снимки обеих тем: `design/screens/passport/`.

Если после отдельного перезапуска/пересоздания API адрес `:8000` работает, а
`:8080` возвращает 502, перезапустите `web`: Nginx мог сохранить прежний IP
контейнера API. При обычной пересборке запускайте оба сервиса `api web`.

```sh
uv sync --all-packages --group dev
uv run pytest backend/tests ml/tests
# С настроенным DATABASE_URL локального PostGIS:
FIREWATCH_POSTGIS_TEST=1 uv run pytest backend/tests/test_events_postgis.py
```

PostGIS-проверка использует временные таблицы в отдельной транзакции и откат;
не изменяет сцены, термоточки или результаты проекта. Проверяются пересечения,
приоритет сильной степени и сумма площадей предварительного восстановления.
