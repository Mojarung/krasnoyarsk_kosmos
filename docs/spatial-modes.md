# Визуальные режимы паспорта

Откройте паспорт гари. «Участки работ» показывает предварительные действия
по опубликованным степеням повреждения и покрову из `aux`. Нажмите на участок,
затем «Назначить осмотр»: место, цель восстановления и причина перенесутся
в существующий мастер. Место остановки не назначается автоматически.

«После пожара» сравнивает архивный и свежий снимки непосредственно на карте.
Разделитель перетаскивается или управляется стрелками, Home и End.
Обе стороны перемещаются и масштабируются вместе. При отсутствии пригодной
пары сравнение не подменяется другими изображениями. «История по годам»
открывает прежний экран наблюдений. Escape возвращает паспорт.

API: POST/GET `/api/v1/events/{id}/work-map`. POST идемпотентно создаёт задачу;
GET возвращает `idle/queued/running/ready/error`. Геометрия и площади доступны
только у готового результата. RabbitMQ: `work-map.prepare`, результат в S3.
Кеш зависит от времени обработки сцен и правил восстановления. Новых таблиц нет.

Пересечения сцен принадлежат более поздней дате «после», затем меньшему ID.
Пропуски покрова не заменяются данными старой сцены и не означают отсутствие работ.
Площади легенды рассчитаны по непересекающейся геометрии этого слоя; это не
автоматическое назначение лесовосстановления и не смета.

Проверка 19.09.2026: реальные участки `bs-FE06923`, `bs-FE08918`,
`bs-BS_live_ff24d9fb`; для сравнения готова пара у `bs-FE06923`:
05.09.2020 / 13.09.2026. В локальном наборе нет многосценовых событий:
приоритет перекрывающихся сцен проверяется синтетическими тестами.

Целевые тесты: `backend/tests/test_work_map.py`, `backend/tests/test_vegetation.py`,
`frontend/tests/e2e/spatial.spec.ts`. E2E сужает только список паспортов до реальной
фикстуры; расчёт, карта, выбор участка, API и изображения используются настоящие.
Отдельные сценарии ошибок и поздних ответов используют подмену ответа API.
