# Кордон — карта проекта

Мониторинг природных пожаров по ДЗЗ, КосмоХакатон 2026. Два ML-модуля (активное горение по VIIRS, гари и степень поражения по Sentinel) и сервис поверх них.

Запуск, устройство конвейера, переменные окружения, API — в `README.md`. Здесь только то, чего в нём нет.

```
backend/      FastAPI + FastStream-воркеры, alembic, src/, tests/
ml/           два модуля инференса, src/, tests/
research/af/  эксперименты по активному горению
frontend/     Vue 3.5 + Tailwind 4 + shadcn-vue (reka-ui) + MapLibre 6 + GSAP + Pinia
design/       дизайн-процесс: brief.md, tokens.md, handoff.md, screens/, reviews/, directions/
.claude/      агенты designer и design-jury, проектные скиллы
```

- Пакетник Python — `uv`, фронт — `npm`. Данные в `DATA/` в git не идут.
- `frontend/src/styles.css` — единственный источник дизайн-токенов. Полный набор CSS-переменных, тёмная тема через `.dark`, огненная шкала вынесена отдельно: `--sev-1`, `--sev-2`, `--sev-3`, `--fire`.

## Маршрутизация: что грузить и когда

Не грузи больше двух дизайн-скиллов на задачу. `taste` — 88 КБ, `impeccable` тянет `reference/*` по мере надобности; загруженные «на всякий случай», они съедают контекст, который нужен под сам экран.

| Ситуация | Грузить | Не грузить |
|---|---|---|
| Новый экран, крупная переделка UI приложения | `impeccable` в режиме **product** — он ведёт процесс | `taste` (его стоп-лист продублирован ниже), `frontend-design` |
| Питч-страница, лендинг, презентационный экран | `impeccable` в режиме **brand** + `taste` | |
| Точечная правка одного компонента, одно CSS-свойство | ничего, хватает правил ниже | любой дизайн-скилл |
| «Сделай как у X», назван бренд или стиль | `awesome-design` → ровно один DESIGN.md → затем `impeccable` | второй DESIGN.md |
| Прислан макет или скриншот интерфейса | `image-to-code` + `impeccable` | |
| Аудит существующего UI перед переделкой | `/impeccable audit` или `redesign` — что-то одно | оба сразу |
| Скриншот-проверка | `playwright-cli` | `claude-in-chrome` (см. ниже) |
| Доступность перед мержем | `accessibility-scan` на экран, `accessibility-audit` на всё | `web-design-guidelines` как замена — только как дополнение по коду |

## Приоритет при конфликте

`этот раздел` > `промпт агента (designer / design-jury)` > `impeccable` > `frontend-design` > `taste`

`taste` подключается ради калибровки трёх ручек и стоп-листа, а не ради стека: `DESIGN_VARIANCE=4`, `MOTION_INTENSITY=3`, `VISUAL_DENSITY=6`.

## Стек: применяем принципы, не стек

Все дизайн-скиллы по умолчанию пишут React/Tailwind/Motion/GSAP. У нас **Vue 3.5 + Tailwind 4 + shadcn-vue (reka-ui)**. Берём из них типографику, шкалу отступов, работу с цветом, состояния и моушен — и переводим на наш стек. React-компоненты, `useMotionValue`, `framer-motion` и прочий чужой рантайм в проект не добавляем. Новые зависимости — только после проверки, что они уместны.

## Источник токенов

`frontend/src/styles.css` — единственный. Из него берутся цвета, радиусы, тени, шрифты.

- Новый DESIGN.md не заводим. Если `awesome-design` или `impeccable` предложат его создать — он описывает то, что уже есть в `styles.css`, а не конкурирует с ним.
- `/impeccable init` пишет `PRODUCT.md` (аудитория, задача, ограничения) — это не токены, конфликта нет, заводить можно.
- Правило «огненные цвета только у данных» уже реализовано: `--sev-1/2/3` и `--fire` существуют отдельно от `--primary`. Правило ниже его фиксирует, а не вводит.

## Скриншот-проверка

Любое изменение UI заканчивается скриншотами через Playwright в `design/screens/`. Вёрстку вслепую не сдавать.

- Ширины: **1440, 768, 375**.
- Проверять и **высоту**: на ноутбучных 1440×800 закреплённые панели съедают экран, а на высоком мониторе всё сходится. Минимум одна проверка на низкой высоте.
- `--full-page` врёт, когда скроллится внутренний контейнер, а не документ. У нас карта на 60% экрана и панели со своим скроллом — это ровно наш случай: нужный контейнер снимать отдельно.
- Всплывающие уведомления и тултипы перекрывают интерфейс в момент показа, а скриншот покоя их не видит. Состояния с оверлеями снимать отдельно.
- Обе темы, светлая и тёмная.
- `claude-in-chrome` для этих проверок не годится: вкладки отдают `visibilityState: "hidden"`, расширение блокирует доступ к куке. Чистые прогоны — только Playwright.

## Детектор impeccable (хук)

Включён машинно-локально: `.claude/settings.local.json` (в `.gitignore`, у каждого свой).

- `PostToolUse` на `Edit|Write` — немедленный тир по файлу, который только что правили: сломанные картинки, обрезанный контент, контраст, градиентный текст, дрейф от дизайн-системы. Таймаут 5 с.
- `Stop` — полный набор правил по всем UI-файлам, которых касались за сессию: ритм вёрстки, палитра, типографика, копирайт. Таймаут 30 с.
- Сканируются `.vue`, `.css`, `.ts`, `.js` и прочие фронтовые расширения. Питон и бэкенд не трогает.
- Движок — бинарник 14,7 МБ в `~/.impeccable/bin/0.1.5/`, качается один раз с GitHub-релизов и проверяется по SHA256. Сети в рантайме не требует, ключей не просит.
- Находку **чинить**, а не заглушать. Если это осознанное исключение — узкий `ignore-value` с `--reason`; `ignore-file` и `ignore-rule` только с явного согласия.
- Выключить в проекте: `/impeccable hooks off`. Разово на шелл: `IMPECCABLE_HOOK_DISABLED=1`.
- Команде хук не навязан: чтобы включить у себя, скопировать манифест из `.claude/skills/impeccable/` или выполнить `/impeccable hooks on`.

## Пол качества (проверяется перед каждой сдачей)

Адаптив до 375 px без горизонтального скролла, видимый фокус с клавиатуры, `prefers-reduced-motion`, состояния загрузки / пусто / ошибка, контраст текста ≥ WCAG AA.

Контраст и доступное имя контрола **не проверяются чтением кода**: `aria-label` в исходнике может лежать на обёртке, а не на самом контроле, а замер контраста обходом предков слеп к абсолютно позиционированному соседу. Гонять `accessibility-scan` по живой странице, а не глазами по шаблону.

## Принципы «Кордона»

1. **Вычитание важнее добавления.** Каждая итерация уменьшает количество текста, плашек и панелей. Прежде чем добавить элемент, попробуй убрать два.
2. **Текстовый бюджет.** Подписи до 3 слов. Никаких поясняющих подзаголовков под пунктами меню и заголовками. Никаких фраз, пересказывающих график. Объяснения только по запросу (тултип). Число важнее слова.
3. **Карта главная.** На обзорном экране она занимает не меньше 60% площади, открыта одна основная панель, остальные свёрнуты.
4. **Цвет означает смысл.** Огненные цвета (жёлтый → оранжевый → красный) только для данных о пожаре и степени поражения. Кнопки, активные состояния и фоны нейтральные плюс один не-огненный акцент.
5. **Одна wow-сцена:** слайдер «до/после» и, если будет, анимация пролёта спутника. Декоративной анимации больше нет.
6. **Запрещено:** подписи капсом, мета-строки через « · », один радиус на всём, карточка в карточке, градиентные подложки, иконка у каждой строки.
7. **Тест проектора:** интерфейс читается на яркости 30% и с 3–5 метров.

Отдельно для космо-хакатона: чёрный фон со звёздами, фиолетово-синий неон и Orbitron — то, что сделают все. Космос ищем в данных, телеметрии, орбитальной механике и инженерной документации.

## Цикл designer ↔ design-jury

Агенты в `.claude/agents/`, пошаговые промпты — в `design/prompts-pipeline.md`.

- `designer` пишет и правит, `design-jury` только оценивает и выдаёт PASS/FAIL. Жюри снимает свои скриншоты, скриншотам дизайнера не верит.
- Цикл повторяется, пока жюри не выставит PASS. Блокеры чинятся первыми.
- Оба агента ходят к скиллам через `Skill`, а к Playwright — через `Bash` (`npx playwright`) или инструменты `mcp__playwright__*`.
- Вердикты копятся в `design/reviews/iteration-N.md`, чтобы был виден прогресс.

## Чего не делать

- Не начинать с кода, пока нет `design/brief.md` и `design/tokens.md`.
- Не объявлять работу готовой без скриншотов.
- Не трогать логику, API и данные ради дизайна. Если без этого не обойтись — сначала спросить.
